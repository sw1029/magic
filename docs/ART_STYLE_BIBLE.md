# Art Style Bible

`Magic Exam Hall`의 모든 시각 자산이 따라야 하는 규칙이다. 한 번 lock되면 PR 리뷰의 기준이 되고, 이 문서와 어긋나는 자산은 머지하지 않는다.

본 문서는 [docs/ART_OVERHAUL_PLAN.md](ART_OVERHAUL_PLAN.md) Phase 0의 산출물이며, [docs/SPRITE_GUIDE.md](SPRITE_GUIDE.md)의 PNG 도입 규칙 위에 위치한다.

## 1. 시점과 카메라

- **시점**: Top-down 3/4 oblique. 카메라 각도 약 45° 기울인 느낌으로 자산을 그린다.
  - 캐릭터 정수리가 약간 보이지만 얼굴이 정면에 가깝다.
  - 가구·벽은 정면 + 윗면 약간 노출(Stardew/Sea of Stars 방식).
  - 순수 top-down(정수리만 보이는 시점)은 금지. 캐릭터 표정·룬 형태 식별에 불리.
- **카메라**: `Pixel Perfect Camera`
  - Reference Resolution: **384×216**
  - PPU: **32**
  - Crop Frame: Pillarbox + Letterbox
  - Stretch Fill: OFF
  - Upscale Render Texture: ON

## 2. 해상도

| 자산 종류 | 해상도 | PPU | 비고 |
| --- | --- | --- | --- |
| 캐릭터(플레이어, NPC) | **48×64 px** | 32 | 후드·로브·손 모션 표현 |
| 타일(바닥·벽) | **32×32 px** | 32 | 1 타일 = 1 world unit |
| 소품(촛불·책장·러그) | 32×32 또는 48×48 | 32 | 크기에 맞춰 선택 |
| 룬(시전 결과) | **64×64 px** | 32 | family 식별성 우선 |
| 이펙트(펄스·파티클) | 32×32 또는 64×64 | 32 | charge 프레임 포함 시 더 큼 |
| UI 아이콘 | 16×16 또는 32×32 | 32 | HUD/노트용 |

**금지**: 같은 카테고리 내 해상도 혼용. 예를 들어 캐릭터 중 누구는 32×32, 누구는 48×64 같은 혼용은 금지.

## 3. 팔레트

**채택 팔레트: [AAP-64](https://lospec.com/palette-list/aap-64)**

- 64색이지만 실제로 한 자산에서 쓰는 색은 6~12색.
- 어두운 마법탑 톤·따뜻한 양초빛·차가운 룬 빛이 모두 표현 가능.
- 외부 팩(Mystic Woods 등) 도입 시 Aseprite `Adjust Colors → Map to Palette`로 AAP-64로 통일.

**금지**:

- 팔레트 외 색 사용(스포이트 픽킹 금지)
- `Shade(c, k)`·`Mix(a, b, t)` 같은 코드 즉석 생성색(절차 폴백 한정 허용, PNG에는 금지)
- 층별 tint 곱셈으로 팔레트 밖 색 만들기(허용되지만, 결과가 다른 팔레트 색에 매핑되는지 확인)

**층별 톤 분리는 팔레트 안에서**: 1층은 따뜻한 톤(brown/orange 계열), 4층 균열층은 차가운 톤(blue/purple 계열), 5층 final seal은 white/gold 강조. 모두 AAP-64 안에서 선택.

## 4. 라이팅 방향

- **광원 방향: 좌상단 → 우하단** (모든 자산이 동일하게 따른다)
- 캐릭터: 좌측 상단부터 하이라이트, 우측 하단부터 그림자
- 가구·벽: 상단·왼쪽 면이 밝고, 하단·오른쪽 면이 어두움
- 룬: 자체 발광이므로 광원 무관하지만, family 색의 다크 셰이드를 우측 하단에 추가해 정합성 유지

**금지**: 자산마다 다른 광원 방향. 그림자가 서로 다른 방향이면 화면 전체가 어색해진다.

## 5. 외곽선 규칙

- **검정 단색 외곽선 금지**. [PixelArtFactory.cs](../unity/MagicExamHall/Assets/MagicExamHall/Scripts/Runtime/PixelArtFactory.cs)가 사용하는 `Color(0.035f, 0.032f, 0.045f, 1f)` 같은 거의 검정 외곽선이 절차 그림이 "값싸 보이는" 핵심 원인.
- **각 영역 색의 다크 셰이드(채도 유지, 명도만 30~40% 낮춤)를 외곽선으로 사용**.
  - 예: 빨간 로브의 외곽선은 다크 적색, 검정 아님.
- 자산 외곽 전체에 외곽선 두를 필요 없음. 배경과 같은 색 영역(예: 어두운 바닥 위 어두운 망토 끝)은 외곽선 생략 가능.
- 캐릭터 실루엣은 1픽셀 외곽선이 기본. 룬은 자체 발광이라 외곽선 없이 가능.

## 6. 셰이딩

- **클러스터 셰이딩**: 픽셀이 1개씩 흩어지지 않게 2~4개씩 뭉쳐 표현.
- **3톤 룰**: 한 영역은 base + light + dark 3색이면 충분. 5톤 이상은 흐려 보임.
- **선택적 안티앨리어싱**: 곡선 가장자리 1픽셀에 중간 톤. 전체 곡선에 적용 금지.
- **디더링**: 두 색 사이 그라데이션 필요 시 체커보드 패턴. 단, 작은 자산(32 미만)엔 사용 자제.

## 7. 룬 가독성 룰

룬은 핵심 메커닉이므로 별도 규칙.

- **40% 축소 시에도 family 5종 구분 가능**해야 한다. PR 리뷰 시 64×64를 26×26으로 축소한 비교 이미지 첨부 권장.
- **각 family는 형태로 우선 구분, 색은 보조**:
  - Fire: 위로 솟은 닫힌 삼각형
  - Water: 닫힌 원형 루프
  - Wind: 평행한 열린 세 줄
  - Earth: 아래가 넓은 사다리꼴
  - Life: 줄기 + 위로 갈라지는 두 가지
- charge 프레임은 base sprite와 같은 형태 + 발광 강도만 다르게. 형태가 바뀌면 인식 표현 매핑이 깨진다.

## 8. 애니메이션 프레임 규약

| 상태 | 프레임 수 | 길이 | 비고 |
| --- | --- | --- | --- |
| idle | 2 | 0.5초 주기 | 호흡 |
| walk | 4 | 0.4초 주기 | 4방향 동일 사이클 |
| cast_charge | 3 | 0.3초 일방향 | charge → release로 이어짐 |
| cast_release | 2 | 0.15초 일방향 | 이후 idle 복귀 |
| rune_charge | 3 | 시전 길이에 동기 | 시간 가변 |

프레임 파일명 컨벤션:

```
<kind>_<state>_<direction>_<index>.png
예: Player_walk_down_0.png, Player_cast_charge_2.png
방향 없는 자산은 direction 생략: Candle_flicker_0.png
```

## 9. 자산별 톤 가이드

- **플레이어**: 흰색~크림 로브, 어두운 갈색 머리, 손목 금장식. 진지한 인상.
- **NPC**: 가능하다면 플레이어보다 살짝 채도 낮춰 주인공이 시선 끌게.
- **바닥**: 짙은 회청색 돌. 1층은 따뜻하게, 4층은 차갑게 tint.
- **벽**: 바닥보다 한 단계 어둡고 한 단계 차가운 톤.
- **양초**: 황동 + 따뜻한 노랑 불꽃. Point Light 2D 색과 일치.
- **룬**:
  - Fire: 따뜻한 주황 + 흰 코어
  - Water: 청록 + 흰 하이라이트
  - Wind: 연한 회청록 + 흰 끝점
  - Earth: 갈색 + 골드 코어
  - Life: 풀빛 녹색 + 흰 새싹

## 10. 금지 사항 요약

| 금지 | 이유 |
| --- | --- |
| 팔레트 외 색 사용 | 톤 깨짐 |
| 검정 단색 외곽선 | 값싸 보임 |
| 자산마다 다른 광원 방향 | 화면 어색 |
| 캐릭터 해상도 혼용 | 캐릭터 비교가 어색 |
| 5톤 이상 셰이딩 | 흐려 보임 |
| 코드 즉석 생성색을 PNG에 사용 | PR 리뷰 불가 |
| charge 프레임에서 룬 형태 변경 | 인식 표현 매핑 깨짐 |

## 11. 변경 절차

본 문서를 수정하려면:

1. 변경 사유를 PR 본문에 명시
2. 기존 자산에 미치는 영향(재작업 필요 자산 목록) 첨부
3. 팀 3인 리뷰 승인
4. 변경 후 진행 중인 자산 PR은 새 규칙으로 재검토

스타일을 자주 흔들면 자산이 누적되지 않는다. 본 문서는 신중하게만 바꾼다.
