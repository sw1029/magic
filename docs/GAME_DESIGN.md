# Magic Exam Hall Game Design

이 문서는 `Magic Exam Hall`이 "동작하는 프로토타입"에서 "끝까지 플레이할 만한 짧은 게임"이 되기 위해 필요한 기획 기준을 정리한 문서입니다. 구현 세부보다 먼저, 플레이어가 무엇을 보고, 듣고, 어떤 순서로 어떤 감정을 거치는지를 기록합니다.

`docs/PROJECT_ROADMAP.md`가 "지금까지 무엇이 구현됐고 다음에 무엇을 할지"를 본다면, 이 문서는 "왜 그 다음 것을 해야 하는지, 끝까지 가면 어떤 게임이 남는지"를 본다.

## 0. 한 줄 요약

플레이어는 떠 있는 마법탑의 입학생이 되어 맵 바닥에 직접 문양을 그리고, 그 문양이 세계 안에서 빛나며 발동하는 것을 보며, 정답 주문이 아니라 관찰과 조합으로 5층 시험을 통과한다.

## 1. 게임 정체성

### 한 문장

`Magic Exam Hall`은 2D top-down 시점의 실시간 마법 드로잉 퍼즐 어드벤처다.

### 본질적 약속

- 플레이어는 메뉴를 열지 않는다. 맵 위에 직접 그린다.
- 문양은 UI 미니게임이 아니라 세계 안의 행동이다.
- 기본 문양은 세계를 바꾸는 동사다.
- overlay 장식은 동사의 방식과 성질을 바꾼다.
- 시험은 정답 주문이 아니라 목표 상태 달성으로 통과한다.
- 실패는 처벌이 아니라 관찰과 다음 실험의 단서다.

이 여섯 줄은 모든 디자인 결정의 기준이다. 새 기능이 이 중 어느 줄을 약하게 만든다면, 그 기능 대신 다른 방향을 찾는다.

### 비슷한 게임들의 자리

먼저 정확히 비교한다. 비슷한 입력이나 비슷한 퍼즐 톤을 가진 게임들은 분명히 있다.

| 게임 | 년도 | 입력 방식 | 마법·퍼즐 다루는 방식 | 이 자리에서 비는 것 |
| --- | --- | --- | --- | --- |
| `Black & White` | 2001, Lionhead | 마우스 제스처로 기적 시전 | 신·도덕 시스템 안의 한 서브 메커닉 | 그리는 행위 자체가 게임의 중심은 아님. 종교 시뮬레이션이 본진 |
| `Arx Fatalis` | 2002, Arkane | 마우스로 룬 모양 그려 주문 발동 | 정답 룬을 외워 그리는 RPG의 한 서브 시스템 | "정답 레시피 외우기"가 핵심. 자유로운 조합 실험은 없음 |
| `Magicka` | 2011, Arrowhead | 키보드 4원소 조합 | 즉발성 액션, 조합 폭의 재미 | **그리는 행위가 아니라 키 누름**. 손으로 그리는 손맛은 없음 |
| `The Witness` | 2016, Thekla | 패널 위 선 그리기 | 정답 레시피 없는 발견형 퍼즐 | 조용한 미로 퍼즐. 시연·반응·실시간 세계 변화 없음 |
| `Inscryption` | 2021, Daniel Mullins | 카드 선택 | 마법·룬을 카드 시스템으로 추상화 | 직접 그리는 행위가 아예 없음 |
| 일반 마법 액션 RPG | — | 단축키/콤보 | 미리 정해진 주문 책에서 고르기 | 시전의 손맛도, 발견의 자유도도, 둘 다 약함 |

20년 동안 이 게임이 만들려는 자리는 거의 비어 있었다. **마우스로 직접 그리는 마법** (Arx Fatalis 라인) + **정답 레시피가 없는 관찰형 퍼즐** (The Witness 라인) + **실패가 처벌이 아니라 단서가 되는 학습 톤** 셋의 교차점에 자리한 게임이 거의 없다. 세 축 중 둘만 가진 게임은 많지만, 셋 다 가진 짧은 작품은 사실상 없다.

### 왜 이 게임이 필요한가

위의 빈자리는 단순한 장르적 빈자리가 아니다. 세 가지 이유로 의미가 있다.

**플레이어 입장 — 다른 게임에서는 못 얻는 것**

- 키 콤보 마법 게임은 손에 입력이 남지 않는다. 그리는 마법은 같은 주문이라도 "내가 어떻게 그렸는가"가 결과에 묻어 손에 흔적이 남는다.
- 정답 레시피 게임은 시험 전날 외워서 통과하는 시험과 닮았다. 이 게임은 시험장 안에서 직접 실험하며 통과하는 시험에 가깝다.
- 처벌형 실패는 다시 시도할 의욕을 깎는다. 이 게임은 실패해도 화면 한쪽 NPC가 다음 단서를 한 줄 던지고 사라진다. 시도가 가벼워진다.

**작품 자체로서 — 짧지만 자기 자리를 가진 게임**

- 1회차 30~60분에 끝나는 짧은 분량은 "포트폴리오 게임"으로도 "수업 발표용 데모"로도 의미가 있다.
- 같은 시간에 다른 마법 게임으로는 얻을 수 없는 한 가지 — **자기 손으로 그어 본 마법진이 작동하는 첫 순간** — 을 제공한다.
- 비교 가능한 동시대 작품이 없기 때문에 "또 하나의 비슷한 게임"이 아니라 "이전에 없던 한 편"이 된다.

**제작 입장 — 왜 굳이 만들 가치가 있는가**

- 마법 게임 시장의 빈 자리이면서, 만드는 데 필요한 핵심 기술(stroke 인식, 품질 분석, 단계적 피드백)은 이미 검증된 기법의 조합으로 도달 가능하다. 즉 야심은 큰데 실현 가능성은 명확하다.
- HCI 관점에서도 "실패-회복형 입력 시스템"의 작은 사례 연구로 쓸 수 있다 (`PROJECT_ROADMAP.md` §1의 핵심 연구 질문 참고).
- 위의 빈자리에 정확히 한 작품을 놓는 것 자체가 결과물이다. 거대한 게임이 아니라 정확한 게임을 만드는 일이다.

이 세 가지가 "왜 다른 마법 게임 대신 이걸 만들고, 왜 플레이어가 다른 마법 게임 대신 이걸 골라야 하는가"의 답이다.

## 2. 대상 경험

### 플레이어 판타지

플레이어는 입학생 마법사다. 교관에게 정답을 받아 적는 학생이 아니라, 살아 있는 마법탑 안에서 직접 문양을 시도하고 룬의 반응을 관찰한다. 시험은 평가를 위한 것이 아니라, 플레이어가 자기 방식으로 마법탑의 언어를 익혔다는 증거다.

### 감정 곡선

1. 낯선 탑에 들어온다. (호기심)
2. 처음 그린 문양이 실제로 바닥에서 빛나며 작동한다. ("어, 됐다.")
3. 같은 문양을 다르게 그렸을 때 결과가 미세하게 다르다는 것을 깨닫는다. (관찰)
4. overlay 장식을 발견하고 같은 base 주문이 다르게 변하는 것을 본다. (재미)
5. 의도한 대로 안 됐을 때 NPC가 짧게 등장해 단서를 주고, 그 말이 노트에 자동 기록된다. (납득)
6. 마지막 층에서 자신이 배운 문법으로 대형 마법진을 복구한다. (자율감)
7. 정답을 맞힌 것이 아니라, 자기 방식으로 시험을 통과했다고 느낀다. (성취)

### 핵심 재미 (loop)

```
관찰 → 그린다 → 세계가 반응한다 → 관찰을 갱신한다 → 다시 그린다
```

이 루프가 30초 단위로 끊임없이 돌아야 한다. 한 문양을 그리고 5초 안에 어떤 반응이라도 (성공이든 흐릿한 파문이든) 와야 한다.

## 3. 세계와 서사

### 배경

무대는 하늘에 떠 있는 오래된 마법탑이다. 입학 시험장이지만 단순한 시설이 아니라, 스스로 반응하고 기록하는 살아 있는 장소다. 탑은 완전히 고장 난 상태는 아니지만 오래된 입학 마법진이 불안정해서, 입학생이 직접 각 층을 안정시키며 올라간다.

### 안내자: Exam Mentor, 그리고 기록부 마법 노트

이 게임의 안내 채널은 한 명의 NPC와 한 권의 기록부로 나뉜다.

**Exam Mentor**는 시험을 안내하는 입회 마법사이고, 게임의 모든 능동 안내를 맡는다. 첫 발견·실패·층 완료처럼 의미 있는 순간에 화면 한쪽에서 짧게 등장해 1~3줄을 말하고, 한 박 뒤 페이드한다. 항상 따라다니지도, 한자리에 머무르지도 않는다. 등장 트리거와 톤 규칙은 §13에서 본다.

대사 예시:

- "물은 흐름을 따라간다."
- "닫히지 않은 자리에서 힘은 새어 나간다."
- "축은 잘린 뒤에야 선다."
- "이번엔 더 천천히 그어 보라."

**마법 노트**는 플레이어가 입학할 때 받은 기록부다. 능동 교사가 아니라 NPC의 말과 자신의 발견을 자동으로 받아 적는 codex다. 게임 진행 중에는 화면 우상단에 책 아이콘이 있고, NPC가 말하거나 새 발견이 생길 때 짧게 펄스로 반응한다. pause 키로 열면 그동안 모인 기록을 카테고리로 다시 볼 수 있다. 노트 자체가 새로운 정보를 만들지 않는다는 점이 중요하다.

노트의 상세 동작은 §13.1에서 본다.

### 서사 목표

플레이어의 표면 목표는 입학 시험 통과다. 실제 플레이 목표는 탑의 문양 언어를 자기 방식으로 이해하고, 마지막 마법진을 복구하는 것이다. 두 목표는 마지막에 같은 사건으로 수렴한다.

### 톤

신비롭지만 무겁지 않다. 시험은 엄숙하기보다 호기심을 자극하는 형태다. 대사와 노트 문장은 시적이되 짧고, 한 문장에 하나의 이미지만 담는다.

## 4. 조작과 맵 위 직접 드로잉

### 기본 조작

| 입력 | 행동 |
| --- | --- |
| WASD / 방향키 | 이동 |
| 우클릭 hold | 마우스 위치의 바닥에 stroke를 그림 |
| 우클릭 release | 현재 stroke 종료 |
| 짧은 시간 안에 다시 우클릭 | 같은 주문 입력의 다음 stroke로 묶임 |
| 입력 버퍼 종료 (약 0.8초) | 주문 판정 및 발동 |
| ESC | 일시정지 / 종료 옵션 |

좌클릭은 의도적으로 비워둔다. 미래에 추가 행동(예: 노트 열기, 오브젝트 줍기)을 위한 여유 슬롯이다.

### 드로잉 원칙

- 문양 입력은 별도 패널에서 하지 않는다.
- 마우스가 가리키는 맵 바닥에 직접 빛나는 stroke가 남는다.
- 플레이어는 드로잉 중에도 계속 이동할 수 있다.
- stroke는 잠깐 빛나다가 사라지지만, base seal은 정해진 시간 동안 바닥에 남는다.
- 주문 효과는 문양 전체의 중심에서 발생한다.
- UI 위에 마우스가 있을 때는 드로잉 입력을 받지 않는다.

### 다획 입력 버퍼

바람처럼 여러 획이 필요한 문양을 위해 짧은 입력 버퍼를 둔다.

- 우클릭을 떼면 바로 주문이 확정되지 않는다.
- 약 0.8초 안에 다음 stroke가 들어오면 같은 주문군으로 묶는다.
- 0.8초 동안 추가 stroke가 없으면 현재 묶음을 하나의 주문으로 판정한다.

이 버퍼 값은 핵심 조작감을 결정하는 단일 지점이다. 너무 짧으면 wind 같은 다획 문양이 자주 실패하고, 너무 길면 단순 base가 분리되지 않는다. 첫 사용자 테스트에서 가장 먼저 검증할 값이다.

### 시전 위치와 목표 판정

주문은 문양의 중심이 가까운 목표 오브젝트에 영향을 준다. 즉 같은 `earth + steel_brace`도 3층 다리 영역 근처에서 그리면 다리 지지대로 해석되고, 4층 균열 근처에서 그리면 균열 안정화로 해석된다. 같은 주문이 위치에 따라 다르게 작동한다는 사실 자체가 게임의 한 가지 발견이다.

## 5. 마법 문법

마법은 `base family`와 `overlay operator`로 구성된다.

### Base family — 세계를 바꾸는 동사

| Base | 문양 | 세계 동사 | 대표 반응 |
| --- | --- | --- | --- |
| Fire | 위로 솟은 닫힌 삼각형 | 점화, 가열, 활성화 | 불씨 점화, 얼음 약화, 오래된 룬 깨움 |
| Water | 둥근 닫힌 루프 | 정화, 냉각, 흐름 | 불 진압, 오염 씻기, 물길 생성 |
| Wind | 평행한 열린 세 줄 | 밀기, 회전, 확산 | 기둥 이동, 바람개비 회전, 안개 흩기 |
| Earth | 아래가 넓은 사다리꼴 | 생성, 고정, 지지 | 발판 생성, 흔들림 안정화, 벽 세우기 |
| Life | 줄기와 갈래 Y | 성장, 연결, 회복 | 덩굴 성장, 씨앗 활성화, 끊긴 생명선 연결 |

5개로 고정한 이유: 첫 클리어 시간 30~60분 안에 모두 한 번씩 의미 있게 쓰이려면 5개가 한계다. 더 많으면 일부는 단발 등장이 되어 학습 가치가 떨어진다.

### Overlay operator — 동사의 방식을 바꾸는 장식

| Overlay | 문양 성격 | 변형 역할 |
| --- | --- | --- |
| `steel_brace` | 열린 브레이스 | 구조 보강, 지속시간 증가, 안정화 |
| `electric_fork` | 갈라지는 번개 | 효과 분기, 회로 전도, 연쇄 반응 |
| `ice_bar` | 수평 막대 | 냉각, 고정, 정지 |
| `soul_dot` | 작고 닫힌 점 | 집중, 정밀 타격, 핵심점 지정 |
| `void_cut` | 대각 절단 | 연결 절단, 오염 분리, 흐름 차단 |
| `martial_axis` | 축선 결합 | 힘의 방향 정렬, 후속 추진, 축 기반 강화 |

`martial_axis`는 `void_cut`이 먼저 붙은 seal에서만 의미 있게 작동한다. 이 의존성은 의도된 깊이를 만든다. "잘랐기 때문에 축이 선다"는 인과를 손으로 발견하는 순간이 게임의 가장 작은 보상이다.

### Base와 overlay 관계

1. 플레이어가 맵 위에 base 문양을 그린다.
2. base가 인식되면 그 위치에 짧게 유지되는 임시 seal이 생긴다.
3. 플레이어가 같은 seal 근처에 overlay를 그리면 해당 base에 붙는다.
4. 붙은 overlay는 주문의 성질을 바꾼다.
5. 한 seal에 붙일 수 있는 overlay 수는 최대 3개로 제한한다 (현재는 잠정 값, 테스트로 조정).

### 자유도 원칙

모든 base와 overlay는 처음부터 시도 가능하다. 게임은 "이 문양은 아직 해금되지 않았습니다"라고 막지 않는다.

대신 플레이어는 환경 반응을 통해 각 문양의 의미를 발견한다. 시험은 특정 레시피를 요구하지 않고, 방의 목표 상태를 만족하면 통과된다.

## 6. 품질 시스템

문양 품질은 성공·실패만 가르는 처벌 장치가 아니다. 품질은 주문의 세기, 지속시간, 안정성, 범위에 영향을 준다.

| 품질 요소 | 의미 | 게임 영향 |
| --- | --- | --- |
| Closure | 닫힌 문양의 끝점 완성도 | 닫힌 주문의 안정성, 유지 시간 |
| Smoothness | 선의 매끄러움 | 흐름·물·바람 계열 효과 안정성 |
| Tempo | 시전 속도 | 즉발성, 확산력, 불꽃의 번짐 |
| Stability | 흔들림과 속도 변화 | 주문 실패율, 효과 떨림 |
| Rotation Bias | 축과 방향의 편향 | 축 기반 효과와 이동 방향 |

### 품질 처리 원칙

- 명백히 잘못된 입력은 주문으로 발동하지 않고 흐릿한 파문만 만든다.
- 애매하지만 읽을 수 있는 입력은 약한 효과로 발동한다.
- 좋은 품질은 같은 주문의 범위, 지속시간, 안정성을 높인다.
- 품질이 낮아도 플레이어의 실험을 완전히 막지 않는다.

품질을 숫자로 노출하지 않는다. 화면에는 "안정", "흔들림", "빠름" 같은 짧은 단어로만 표시한다. 숫자는 로그에만 남는다.

## 7. 피드백과 노트

### 맵 피드백

| 상황 | 피드백 |
| --- | --- |
| base 성공 | 바닥에 작은 원형 룬이 잠깐 고정되고 효과음과 함께 빛 펄스 1회 |
| overlay 성공 | 룬 가장자리에 작은 장식 마크가 붙고 짧은 글로우 |
| final effect | 문양 중심에서 빛, 파동, 환경 변화가 발생. 카메라 미세 흔들림 |
| invalid input | 흐릿한 파문이 생기고 1초 안에 사라짐. 효과음 없음 |
| low quality | 약하고 불안정한 효과 + "흔들림" 라벨 |
| 위험 접촉 | 화면 가장자리 붉은 비네트, 안전 지점으로 이동 |

### 룬 라벨

문양 위에는 짧은 라벨이 뜬다.

예시: `불꽃`, `물 + 얼음`, `생명 + 집중`, `절단 뒤 축`

라벨은 플레이어가 자신의 입력이 어떻게 해석됐는지 즉시 알게 하기 위한 최소한의 UI다. 한 줄, 한국어, 12자 이내.

### 마법 노트의 자동 기록

노트는 능동 교사가 아니라 codex다. 다음 순간에 자동으로 새 줄이 추가된다.

- NPC가 무언가 말했을 때 — 그 발언 그대로 기록된다.
- 새 반응을 발견했을 때 — "물에 닿은 불이 꺼졌다" 같은 짧은 관찰문이 자동 생성된다.
- 층을 완료했을 때 — 그 층의 짧은 마무리 문장이 추가된다.

플레이어가 직접 노트에 글을 쓰지는 않는다. 노트 갱신은 화면 우상단 책 아이콘 펄스로만 알리고, 게임 진행을 멈추지 않는다. 자세한 codex 구조는 §13.1에서 본다.

### 단계적 힌트 (escalator)

같은 목표에서 같은 종류의 실패가 반복되면 안내가 단계적으로 강해진다. 1단계는 환경이 처리하고, 2단계부터 NPC가 등장한다. **환경 반응이 먼저 말한다. NPC는 그 말이 닿지 않을 때만 나온다.**

| 실패 횟수 | 안내 채널 |
| --- | --- |
| 1회 | 환경만. 룬 라벨 위에 작은 reason 텍스트 1초 ("닫힘이 약함"), `cast_incomplete` 등 적절한 실패 SFX. NPC 등장 없음 |
| 2회 | NPC 등장 1회. family별 체크리스트 2~3줄. 예: "끝점이 시작점에 닿았나. 두 변의 각도가 비슷한가." |
| 3회 이상 | NPC 등장 1회 + 바닥에 ghost trace 1.5초. NPC는 "이런 모양이다" 한 줄만 |

NPC가 등장한 발언은 동시에 노트에 자동 기록된다. 1회 실패의 환경 텍스트는 노트에 기록되지 않는다 (소음 방지). assist를 받고 성공한 시도는 로그에 `assisted=true`로 남지만, 플레이어에게 별도 패널티는 없다.

## 8. 층 구성 — 한 줄 요약

이 게임의 완성판은 5층 마법탑이다. 각 층은 단순한 난이도 단계가 아니라, 마법 문법의 새로운 면을 가르치는 역할을 맡는다.

| 층 | 역할 | 가장 강하게 가르치는 것 |
| --- | --- | --- |
| 1층 발착층 | 입장과 첫 시전 | base 5종이 세계에 영향을 준다는 사실 |
| 2층 반응층 | overlay 발견 | 같은 base가 overlay에 따라 다르게 변한다 |
| 3층 흐름층 | 조합 응용 | 한 목표를 여러 방법으로 풀 수 있다 |
| 4층 균열층 | 실시간 위험 | 그리는 동안에도 세계는 움직인다 |
| 5층 성좌심 | 자유 조합 | 정답이 없는 큰 마법진을 자기 방식으로 푼다 |

층별 상세는 §9에서 본다.

## 9. 층별 상세 시나리오

각 층은 다음 항목으로 정의한다: 들어올 때의 공간, **퍼즐 밀도**, 목표 상태, 가능한 해결 방향, 키 모먼트, 화면 배치, 진행 시간 목표, NPC가 등장하는 자리, 실패 회복 디자인.

### 층별 퍼즐 밀도 요약

| 층 | 풀어야 할 인터랙션 | 통과 기준 | 해결 루트 최소 다양성 |
| --- | --- | --- | --- |
| 1층 | 인덱스 룬 5개 (base 5종에 1:1 대응) | 1개 이상 작동시키면 승강 룬이 차오름. 권장 3개 이상 | 5 base 각각 |
| 2층 | 깨진 룬 6개 (overlay 6종에 1:1 대응) | 4개 이상 복구 | overlay 6종 중 최소 4종 사용 |
| 3층 | 끊긴 다리 1개 | 어느 방법이든 한 경로로 통과 | 최소 4가지 해결 루트 (아래 목록) |
| 4층 | 균열 3개 + 번개 회로 1개 | 모두 안정화 | base+overlay 조합 최소 3가지 |
| 5층 | 슬롯 6개 (상태 요구) | **5개 만족 = 통과 엔딩 / 6개 만족 = 진엔딩** | 슬롯당 만족 방법 최소 2종 |

밀도는 "이 정도가 한 층에서 무리 없이 발견될 분량"의 잠정 값이다. 사용자 테스트에서 조정한다.

### 1층 발착층

**공간** — 탑 입구. 바닥에 5개의 작은 인덱스 룬(불씨, 물웅덩이, 바람개비, 돌기둥, 마른 덩굴)이 흩어져 있다. 가운데에 잠긴 승강 룬이 있다.

**목표 상태** — 승강 룬이 활성화된다.

**가능한 해결 방향** — 5개 base 중 무엇이든 인덱스 룬에 작동시켜 보면 반응이 일어나고, 그 반응이 승강 룬에 점차 차오른다. 5개를 다 시도하지 않아도 통과 가능하지만, 모두 시도하면 노트가 가장 풍부해진다.

**키 모먼트** — 입장 직후 30초 안에 첫 문양이 작동해야 한다. 8초 지점에 발동이 없으면 NPC가 잠깐 등장해 "바닥에 그어 보라"고 한 줄을 던지고 사라진다.

**화면 배치**

```
                    [노트 책 아이콘]
                                 
   불씨     물웅덩이             [층 라벨]
                                 
       바람개비                   
                  [PLAYER]      
   덩굴                          
            돌기둥               
                                 
   [Exam Mentor]                 
            [승강 룬 — 잠김]      
```

층 라벨과 노트 아이콘은 항상 오른쪽 위. 1층은 환경(룬 발광, 라벨, SFX)이 첫 안내를 전부 맡는다. NPC는 입장 한 번, 8초 침묵 시 한 번, 5분 침묵 시 한 번 — 세 자리에만 등장.

**진행 시간 목표** — 평균 5~8분.

**환경이 먼저 가르치는 것 (NPC 없음, 자동 발견)**

base 첫 발동 시 인덱스 룬이 잠깐 빛나고 짧은 SFX. 노트는 "물에 닿은 불이 꺼졌다" 같은 짧은 자동 관찰문을 받는다. NPC 대사는 없다.

**NPC가 등장하는 자리**

- 1층 입장 직후: 환영 한 줄. 예: "바닥은 너의 종이다."
- 입장 8초 안에 발동 없음: "우클릭을 누른 채 바닥에 선을 그어 보라."
- 5분이 지나도 첫 발동 없음: 같은 안내를 한 번 더, 조금 다른 표현으로.

**실패 회복** — 환경 자체가 작동 가능한 인덱스 룬을 항상 시야 안에 두므로 막힘이 적다. NPC는 위 세 자리 외에는 1층에서 등장하지 않는다.

### 2층 반응층

**공간** — 벽화가 가득한 둥근 방. 가운데에 6개의 깨진 룬이 원형으로 배치돼 있다.

**목표 상태** — 6개 깨진 룬 중 4개 이상이 복구된다.

**가능한 해결 방향** — 깨진 룬은 각각 다른 overlay에 반응한다. 플레이어는 base를 먼저 그린 뒤 overlay를 그려야 룬이 복구된다. overlay는 처음부터 모두 그릴 수 있지만, 어떤 overlay가 어떤 룬과 맞는지는 시도로만 알 수 있다.

**키 모먼트** — overlay가 처음 base seal 위에 붙는 순간. 룬 가장자리에 작은 마크가 추가되며 라벨이 `불꽃 + 집중` 같은 형태로 변한다. 이 순간이 "base 위에 무언가를 더 올릴 수 있다"는 발견이다.

**화면 배치**

```
   [노트]                [층 라벨]
                                  
        깨진룬1         깨진룬2     
                                  
   깨진룬6   [PLAYER]   깨진룬3     
                                  
        깨진룬5         깨진룬4     
                                  
   [벽화 — overlay 형태 힌트]      
```

벽화는 클릭하지 않아도 자연스럽게 시야에 들어오게 한다. 정답이 아니라 "이런 모양도 있다"는 단서.

**진행 시간 목표** — 평균 8~12분.

**환경이 먼저 가르치는 것**

- 첫 overlay 성공 시 룬 가장자리에 작은 마크가 추가되고 라벨이 `불꽃 + 집중` 형태로 변한다. NPC 등장 없음.
- `martial_axis` 의존성 부족 시 시도 자체가 잠긴 듯한 `cast_dependency_missing` SFX로 처리되고, 룬 라벨 위에 "축이 설 자리가 없음" 한 줄이 1초 표시. NPC 등장 없음.
- 벽화는 6 overlay의 실루엣 단서를 정적 배경으로 제공한다.

**NPC가 등장하는 자리**

- 같은 깨진 룬에 같은 base로 3회 실패 시 (escalator 2단계). family 체크리스트 한 번.
- 6개 룬 중 4개를 복구해 층 완료 시 한 줄 마무리.

2층은 발견 위주 층이라 NPC 출연이 매우 드물다. 환경 자체가 단서다.

**실패 회복** — 같은 깨진 룬에 같은 base를 두 번 실패하면 그 룬이 5초간 살짝 진동한다. 비언어적 단서로 끝. 세 번째부터 escalator가 NPC로 넘어간다.

### 3층 흐름층

**공간** — 끊어진 공중 다리. 플레이어와 다음 구역 사이에 빈 공간이 있다.

**목표 상태** — 플레이어가 건너편으로 이동할 수 있는 경로가 만들어진다.

**가능한 해결 방향** — 의도된 네 가지 + 발견 가능한 변주.

- `earth + steel_brace` — 빈 공간에 단단한 지지대가 솟아 다리가 됨. 가장 직관적인 해법.
- `wind + martial_axis` — 떠 있는 발판이 일직선으로 정렬되어 건널 수 있음. 발판이 보일 때만 가능.
- `life + soul_dot` — 한쪽 끝에서 덩굴이 자라 반대편에 닿음. 닿을 거리가 짧을 때만 충분.
- `water + ice_bar` — 임시 얼음 다리. 일정 시간 후 녹으니 그 안에 건너야 함.
- (선택적 변주) `earth` 단독으로도 짧은 발판은 가능하지만 길이가 부족함. 두 번 그어 연결해야 함.
- (선택적 변주) `electric_fork`로 끊긴 회로를 잇고 그 위를 건너는 변형도 가능 (성공 시 NPC가 "내가 고른 길이 나의 답이다" 발화).

같은 목표를 다른 방법으로 풀 수 있다는 것을 처음 명시적으로 알려주는 층이다.

**키 모먼트** — 플레이어가 만든 경로 위로 처음 한 발을 내딛는 순간. 카메라가 살짝 줌인된다.

**화면 배치**

```
                    [층 라벨]
                                  
   [건너편 — 다음 층 입구]         
   ──────────────                
                                  
   ────────                       
            (빈 공간)              
                       ──────    
                                  
   [PLAYER]                       
   ─────────                      
```

빈 공간은 의도적으로 시야 한가운데에 둔다. 플레이어 시선이 자연스럽게 "여기를 메워야 한다"로 향하게.

**진행 시간 목표** — 평균 6~10분.

**환경이 먼저 가르치는 것**

- 빈 공간이 시야 한가운데 — "여기를 메우면 된다"는 비언어적 단서.
- 가까운 영역에 base/overlay 시전 시 그 효과가 빈 공간에서 한 번씩 미리 잠깐 비치는 시각 힌트 (예: `earth` 시전 시 작은 돌 부스러기가 빈 공간 가장자리에 잠깐 솟음).

**NPC가 등장하는 자리**

- 층 완료 시 한 줄 마무리. 예: "한 자리에 닿는 길은 여럿이다."
- 두 번째 다른 방법으로 통과 시 (선택적): "내가 고른 길이 나의 답이다." (이 자리는 의도된 보너스라 NPC 등장에 가치가 있음)

**실패 회복** — 만든 경로가 시간 경과로 약해지면 한 번 더 같은 주문을 덧그릴 수 있게 한다. 부분 진행은 유지된다.

### 4층 균열층

**공간** — 불안정한 룬 회로가 깔린 좁은 공간. 번개 회로와 균열이 천천히 퍼지고, 발판이 떠 있다 사라진다.

**목표 상태** — 균열 3개가 모두 안정화되고, 번개 회로가 잠잠해진다.

**가능한 해결 방향** — base+overlay 조합 최소 3가지가 의도된 답.

- `earth + steel_brace` — 균열 봉합. 가장 안정적이지만 시전 시간이 김.
- `water + ice_bar` 또는 `ice_bar` 단독 — 번개 회로 동결. 회로가 멈춤.
- `void_cut` — 균열 진행 차단. 즉발이지만 부분만 막음.
- `wind` 단독 — 떠 있는 발판을 안전 위치로 밀어 안전 지점 추가 (선택, 진행 보조).
- 균열 3개를 모두 같은 방법으로 풀어도 되고, 각각 다른 방법을 써도 됨. 다양성이 통과 조건은 아님.

**키 모먼트** — 그리는 중에 위험이 닿아 안전 지점으로 리셋되는 첫 순간. 게임이 처음으로 "실시간 압박"을 가르치는 순간이다. 화면 가장자리 비네트 + 짧은 효과음 + 즉시 안전 지점 이동. 죽음이나 체력 감소는 없다.

**화면 배치** — 다른 층과 달리 시야 안에 안전 지점(파란 룬)을 항상 1개 이상 보이게 둔다. 카메라가 안전 지점에서 너무 멀어지지 않게 약한 추적 제한을 둔다.

**진행 시간 목표** — 평균 8~12분.

**환경이 먼저 가르치는 것**

- 첫 안전 지점 리셋 시 화면 가장자리 비네트 + `hazard_reset` SFX. 노트는 "탑은 떨어진 사람을 다시 돌려보낸다"를 자동 관찰문으로 기록. NPC 등장 없음.
- 균열 첫 안정화 시 균열이 또렷이 다물리는 시각 변화 + 짧은 `goal_satisfied`. 노트는 "벌어진 자리는 단단한 것이 덮는다"를 자동 기록.

**NPC가 등장하는 자리**

- 같은 균열에 5회 이상 실패 시 (escalator 2~3단계). "그 균열은 단단한 것을 좋아한다" 같은 한 줄. 화면 가장자리 작은 윈도우로 등장해 그리는 손을 가리지 않음.
- 층 완료 시 한 줄 마무리.

**실패 회복** — 무한 리셋이 안전 지점에서 일어나기 때문에 진행이 막히지 않는다.

### 5층 성좌심

**공간** — 탑의 가장 위. 가운데에 큰 마법진이 깨진 채 떠 있다. 마법진은 6개의 빈 슬롯(요구 상태)으로 구성된다. 슬롯은 정해진 주문을 요구하지 않고, 만족할 수 있는 "상태"를 요구한다.

| 슬롯 | 요구 상태 | 만족 예시 |
| --- | --- | --- |
| 정화 | 오염된 자리를 씻는다 | `water`, `void_cut` |
| 안정 | 흔들리는 자리를 고정한다 | `earth + steel_brace`, `ice_bar` |
| 연결 | 끊긴 자리를 잇는다 | `life`, `electric_fork` |
| 집중 | 핵심점을 강하게 활성화한다 | `soul_dot`, `fire + soul_dot` |
| 흐름 | 한 방향의 움직임을 만든다 | `wind`, `water + martial_axis` |
| 절단 | 위협의 연결을 끊는다 | `void_cut`, `wind + void_cut` |

**목표 상태와 두 갈래 엔딩**

- **5개 슬롯 만족 = 통과 엔딩** — 마법진이 안정화되고, 화면이 한 번 밝아진 뒤 BGM이 잦아든다. NPC가 마지막 인사 한 줄을 남기고, 성찰형 리포트가 열린다.
- **6개 슬롯 만족 = 진엔딩** — 통과 엔딩의 모든 연출에 더해, 6번째 슬롯이 만족되는 순간 화면이 한 번 더 천천히 밝아지고 BGM이 한 단계 더 차오른다. NPC가 한 줄을 추가로 남기며, 성찰형 리포트의 헤더가 "당신은 마법진을 완전히 기억한 마법사였습니다"로 변한다.
- 5개에서 멈춰도 게임이 끝나기 직전에 6번째를 시도할 수 있다 (마법진은 5개 만족 후 잠시 더 유지된다).

**키 모먼트** — 첫 슬롯이 만족되어 마법진 한 조각이 빛나는 순간. 카메라가 살짝 줌인되며 BGM이 한 단계 변한다. 5번째 슬롯 만족 순간에는 전체 화면이 천천히 밝아지며 BGM이 정점에 도달하고, 6번째 슬롯이 추가로 만족되면 BGM과 화면이 한 박 더 차오른다.

**화면 배치**

```
                    [층 라벨]
                                  
            정화                  
                                  
    절단              안정        
                                  
       [큰 마법진 중심]            
                                  
    흐름              연결        
                                  
            집중                  
                                  
   [PLAYER]    [Exam Mentor]      
```

6개 슬롯은 시야 안에 한 번에 보이도록 배치하되, 슬롯 라벨은 흐릿하게 떠 있고 만족되는 순간에 또렷해진다.

**진행 시간 목표** — 평균 10~15분.

**환경이 먼저 가르치는 것**

- 슬롯 만족 시 그 슬롯 라벨이 또렷해지고 `goal_satisfied` SFX, 마법진 조각 1개가 점등. 노트는 "마법진은 한 자리씩 깨어난다" 등의 자동 관찰문을 받는다. NPC 등장 없음.
- 슬롯이 4개 만족된 시점에 마법진 전체가 미세하게 떨리기 시작한다. "거의 다 됐다"는 비언어적 단서.

**NPC가 등장하는 자리**

- 5번째 슬롯 만족 직후 (통과 엔딩 시작): "탑이 너의 이름을 기억한다." 같은 한 줄. 마지막 인사.
- 6번째 슬롯이 추가로 만족된 경우 (진엔딩): 그 직후 한 줄 더 등장. 예: "너는 단 하나도 비워두지 않았다."

**실패 회복** — 슬롯 만족은 누적되고 사라지지 않는다. 잘못 그려도 진행이 깎이지 않는다.

## 10. 스토리 아크

5층은 단순한 난이도 단계가 아니라 한 편의 짧은 이야기다.

- **시작** — 1층 입장에서 NPC가 짧게 환영한다. 시험이 무엇인지 거창하게 설명하지 않는다. "바닥은 너의 종이다." 정도의 한 줄.
- **전개** — 1~3층 본문에서는 환경(룬 발광, 라벨, SFX, 노트 자동 기록)이 거의 모든 안내를 한다. NPC는 막혔을 때(2회 이상 실패)와 층 완료 시에만 짧게 등장한다.
- **위기** — 4층의 균열은 탑이 불안정하다는 사실을 보여준다. NPC가 화면 가장자리 작은 윈도우로 들어와 "탑의 입학 마법진이 흔들린다"고 한 줄을 남기고, 그 말이 노트에 기록된다.
- **클라이맥스** — 5층 성좌심에서 5번째 슬롯이 만족되는 순간. 화면 전체가 밝아지고 BGM이 정점에 도달한다. 6번째까지 채우면 한 박 더 차오른다.
- **마무리** — NPC가 다시 등장해 한 줄을 남긴다. "너의 방식이 마법진을 다시 일어서게 했다." 그 뒤 성찰형 리포트가 열린다.

서사의 무게는 환경 자체와 NPC의 드문 컨텍스트 소환, 그리고 노트의 자동 기록이 분담한다. NPC가 게임 톤의 50%를 넘지 않게 한다. 컷씬·긴 대사·NPC 군중은 없다.

## 11. 화면 배치 가이드

### 항상 같은 위치에 있는 요소

- **층 라벨** — 화면 우상단. "1층 발착층 / 6개 슬롯 중 0" 같이 한 줄.
- **노트 아이콘** — 우상단 층 라벨 바로 아래. 갱신 시 짧은 펄스.
- **룬 라벨** — 마법 발동 시 문양 바로 위에 1초간.
- **HUD 메시지** — 화면 하단 중앙, NPC 대사·중요한 안내만. 노트 자동 기록은 여기 띄우지 않고 우상단 책 아이콘 펄스로만 알린다.
- **위험 비네트** — 화면 가장자리 붉은 그라데이션, 위험 접촉 시 1초간.

### HUD 정보 우선순위

화면에 동시에 표시되는 정보는 최대 3개를 넘지 않는다.

1. 층 정보 (항상)
2. 노트 아이콘 (항상)
3. 현재 상황에 가장 중요한 것 하나 (룬 라벨 또는 NPC 대사 또는 위험 비네트)

NPC 대사가 떠 있는 동안 룬 라벨은 위치를 살짝 옮기거나 잠시 페이드된다. 두 메시지가 겹치면 안 된다.

### 시야 디자인

플레이어 캐릭터는 화면 중심 근처에 두지만 정확히 가운데는 아니다. 진행 방향 쪽 1/3 정도를 더 보여주도록 카메라 오프셋을 둔다. 4층은 예외 — 안전 지점이 항상 시야에 들어오도록 카메라가 약하게 끌린다.

### 가독성 원칙

- 모든 텍스트는 16pt 이상.
- 텍스트와 배경 대비를 AA 기준으로 맞춘다.
- 마법 효과의 빛이 텍스트를 덮지 않게 텍스트는 항상 약한 외곽선이 있다.

## 12. 사운드 디자인

현재 구현에 사운드가 없다. 사운드 1차 패스는 게임 인상의 절반을 결정한다. 성공·실패가 귀로 즉시 구분되는 것이 가장 중요하다. 다음을 최소 셋업으로 정의한다.

### 성공 SFX (3종 + family 변주)

| 사운드 | 길이 | 톤 | 용도 |
| --- | --- | --- | --- |
| `cast_base_success` | 0.4s | 짧은 차임 + 부드러운 펄스 | base seal 활성화 |
| `cast_overlay_success` | 0.3s | 더 가벼운 차임 | overlay 부착 |
| `cast_final_effect` | 0.8s | 깊은 풍선·바람 | final effect 발동 |

위 3종은 각각 base family에 따라 ±2~3 semitone의 pitch shift로 다르게 들리게 한다. 같은 샘플 하나에 5개의 변주를 두면 fire는 밝게, water는 부드럽게, wind는 가볍게, earth는 낮고 단단하게, life는 따뜻하게 들린다. 별도 샘플을 5개 만들지 않아도 된다.

### 실패 SFX (3종으로 분리)

플레이어가 귀로 실패의 종류를 구분할 수 있어야 다음 행동이 빨라진다. 단일 `cast_fail`로 묶지 않는다.

| 사운드 | 길이 | 톤 | 용도 |
| --- | --- | --- | --- |
| `cast_invalid` | 0.2s | 흐릿한 한숨 | 인식 자체가 안 된 경우 (의미 없는 stroke 묶음) |
| `cast_incomplete` | 0.3s | 반쯤 차오르다 사라지는 톤 | 형태는 비슷한데 closure·stroke 수가 부족한 경우 |
| `cast_dependency_missing` | 0.25s | 짧은 잠긴 클릭 | 의존성 불만족 (예: `martial_axis`인데 `void_cut` 없음) |

low quality로 발동은 되었지만 약한 경우는 별도 SFX를 두지 않는다. 해당 성공 SFX를 -6dB로 약화 재생하여 "되긴 됐는데 약하다"는 인상을 만든다.

### 기타 SFX

| 사운드 | 길이 | 톤 | 용도 |
| --- | --- | --- | --- |
| `goal_satisfied` | 0.6s | 상승 멜로디 | 층 목표 일부 만족 |
| `floor_complete` | 1.2s | 짧은 stinger | 층 완료 |
| `note_unlock` | 0.3s | 책장 넘김 | 노트 자동 기록 |
| `hazard_reset` | 0.5s | 낮은 진동 | 안전 지점 리셋 |
| `npc_appear` | 0.4s | 부드러운 룬 글로우 | NPC 컨텍스트 소환 |

### BGM

- **ambient_tower** — 1~3층용. 조용한 룸톤. 8~10분 루프.
- **climax_seal** — 5층 시작부터. 한 단계 더 강한 톤. 마법진 1개 만족마다 음 추가.

4층은 BGM을 거의 끄고 환경음(번개 잡음, 균열 갈라짐) 위주로 둔다. 압박감을 음악이 아니라 침묵으로 만든다.

## 13. NPC: Exam Mentor

PR #71에서 추가된 mentor는 게임의 보조 안내자다. **환경 반응이 먼저 말하고, NPC는 그 말이 닿지 않을 때만 나온다.** 첫 발견·평범한 진행은 환경(룬 발광, 라벨, SFX, 노트 자동 기록)이 처리하고, NPC는 막힘·완료·엔딩 같은 의미 있는 자리에만 등장한다.

### 컨텍스트 소환 모델

NPC는 따라다니지도, 한자리에 고정으로 머무르지도 않는다. 다음 6종 트리거에서만 화면 한쪽에서 페이드인하고, 한 박 뒤 사라진다.

| 트리거 | 등장 빈도 | 대사 길이 | 자리의 의미 |
| --- | --- | --- | --- |
| 1층 입장 | 1회 | 1줄 환영 | 시작 시 톤 잡기 |
| 1층 8초·5분 침묵 | 각 1회 | 1줄 조작 안내 | 입구에서 막힘 방지 |
| 같은 목표에서 2회 실패 | 매 발생, 60초 쿨다운 | 2~3줄 체크리스트 | escalator 2단계 |
| 같은 목표에서 3회 이상 실패 | 매 발생, 60초 쿨다운 | 1줄 + 바닥 ghost trace | escalator 3단계 |
| 층 완료 | 층마다 1회 | 1~2줄 마무리 | 마무리 호흡 |
| 5층 5번째·6번째 슬롯 만족 | 각 1회 | 1줄 + 진엔딩 시 1줄 추가 | 클라이맥스와 마지막 인사 |

**의도적으로 제거된 트리거** (이전 11개 → 현재 6개):

- base 첫 발동 5종 — 환경(룬 발광 + 자동 노트)로 충분.
- 첫 overlay 부착 — 룬 가장자리 마크 + 라벨 변화로 충분.
- `martial_axis` 의존성 차단 — `cast_dependency_missing` SFX + 룬 라벨 1초 표시로 충분.
- 같은 목표 1회 실패 — 룬 라벨 위 작은 reason 텍스트 + 실패 SFX로 충분. NPC는 2회부터.
- 5층 슬롯 만족 (1~4번째) — 슬롯 라벨 변화 + `goal_satisfied` SFX로 충분.

같은 트리거 쿨다운은 30초에서 60초로 늘려 재촉감을 더 줄인다.

### 대사 원칙

- 한 등장당 1~3줄.
- 정답을 알려주지 않는다. 방향만 가리킨다.
- 시적이지만 행동 동사를 포함한다 ("바닥에 그어 보라", "단단한 것을 찾아라").
- 같은 트리거여도 텍스트는 여러 변주를 둔다 (한 트리거당 3~5종 풀에서 무작위).

### 시각 표현

- 픽셀 도트, 플레이어보다 키 1.5배, 정적인 idle 애니메이션.
- 화면 우측 또는 가까운 빈 자리에서 페이드인. 장면 안에 머무르지 않는다.
- 대사 중에는 머리 위에 작은 룬이 떠오른다.
- 대사가 끝나면 한 박자 뒤 페이드아웃.
- 4층 같은 압박 상황에서는 화면 가장자리 작은 윈도우로 들어와 그리는 손을 가리지 않는다.

### 노트와의 hook

NPC가 말하는 순간 그 대사가 그대로 마법 노트에 자동 기록된다. 게임 화면에는 화면 우상단 책 아이콘이 짧게 펄스만 한다. 노트의 codex 화면에서 그 줄을 다시 볼 수 있다.

## 13.1 마법 노트 (Codex)

노트는 새 정보를 만들지 않는다. NPC의 대사와 플레이어의 발견을 받아 적기만 한다.

### 게임 진행 중 표시

- 화면 우상단 책 아이콘은 항상 있음.
- 새 줄이 추가될 때 0.4초 펄스 + `note_unlock` SFX.
- 별도 텍스트 박스나 슬라이드인은 없음.

### Codex 열람

- `Tab` 키 또는 책 아이콘 클릭으로 열림. 열면 게임은 잠시 멈춤(soft pause).
- 3개 탭으로 분류.
  - **대사** — NPC가 한 말 모두, 층별·시간순으로 묶임.
  - **층별 노트** — 각 층의 진행 마무리 문장.
  - **발견** — 시도한 base 5종과 overlay 6종을 그리드로. 첫 성공한 항목은 또렷하게, 미발견은 실루엣.
- 닫을 때 `Tab` 또는 `Esc`.

### 엔딩 리포트와의 관계

5층 마지막 슬롯 만족 후 열리는 성찰형 리포트는 노트에서 대표 관찰문 3줄을 자동으로 골라 보여준다 (§16 참고).

## 14. 게임 느낌과 폴리시

다음 9개 모먼트를 "그 순간이 살아 있어야 게임이 산다"고 본다. 각 모먼트는 시각·청각·진동 셋 중 최소 둘을 동시에 줘야 한다.

1. **첫 base 발동** — 빛 펄스 + 차임. 카메라 미세 흔들림 없음 (첫 인상은 부드럽게).
2. **첫 overlay 부착** — 작은 트레일이 base seal로 빨려 들어감 + 가벼운 차임.
3. **3층 첫 경로 통과** — 카메라 짧은 줌인 + 발걸음 사운드 강조.
4. **4층 첫 위험 리셋** — 가장자리 비네트 + 낮은 진동 + 짧은 화면 흐릿함.
5. **노트 자동 기록 새 줄** — 우상단 책 아이콘 0.4초 펄스 + 책장 넘김 사운드. NPC 없이도 일어나는 가장 자주 있는 보상.
6. **assist ghost trace 등장 (escalator 3단계)** — NPC가 짧게 등장해 "이런 모양이다" + 바닥에 흐릿한 모범선 1.5초 + 짧은 종소리. 셋이 동시에.
7. **5층 슬롯 1개 만족** — 슬롯 라벨이 또렷해지며 빛 + 상승 멜로디 1단.
8. **5층 5번째 슬롯 만족 (통과 엔딩 시작)** — 화면 전체 천천히 밝아짐 + BGM 정점 + 카메라 정지 + NPC 마지막 인사 한 줄.
8b. **5층 6번째 슬롯 만족 (진엔딩)** — 한 박 더 화면 차오름 + BGM 한 단계 추가 + NPC 추가 한 줄. 8 직후에만 발생.
9. **엔딩 리포트 열림** — 페이드 + 부드러운 페이지 등장 + 노트 톤의 BGM. 진엔딩 도달 시 헤더 문구가 변한다.

## 15. 접근성

첫 외부 테스터부터 다음 옵션을 제공한다.

- 마우스 좌·우클릭 스왑.
- 키 리바인딩 (이동 4키).
- 마우스 감도 조절.
- 색약 보조 — 위험 비네트와 성공 빛은 색만이 아니라 패턴(점선·줄무늬)으로 구분.
- 텍스트 크기 1.0× / 1.25× / 1.5×.
- BGM·SFX 별도 볼륨.

체력·전투가 없기 때문에 난이도 옵션은 제공하지 않는다. 대신 escalator를 자동으로 1단계 강하게 시작하는 "관찰 모드"를 추가할지 검토한다.

## 16. 로그와 엔딩 리포트

### 로그

세션 내내 다음을 attempts.csv / .jsonl로 남긴다.

- session id, trial id, target, recognized family, recognized overlays, status, quality vector
- assist level, hint shown, assisted success 여부
- 시도 시작/종료 timestamp, stroke 수

raw stroke 데이터는 기본 저장하지 않는다. 별도 모드에서 명시 동의 시에만 저장한다.

### 엔딩 리포트

5번째 슬롯 만족 직후 (또는 6번째까지 채운 직후) 다음 항목을 1화면에 보여준다.

- 엔딩 도달 상태: "통과 엔딩 (5/6 슬롯)" 또는 "진엔딩 (6/6 슬롯)"
- 가장 많이 사용한 base, 사용 횟수
- 가장 많이 사용한 overlay, 사용 횟수
- 발견한 조합 수
- 평균 품질 경향 (1~2단어, 숫자 노출 X)
- 가장 안정적으로 그린 문양
- 가장 많이 실패한 문양
- 노트가 기록한 대표 관찰문 3줄 (codex에서 자동 발췌)
- 자기 평가 4문항 (척도 1~5)

리포트 헤더 문구는 도달 상태에 따라 다르게 둔다.

- 통과 엔딩: "당신은 이런 마법사였습니다"
- 진엔딩: "당신은 마법진을 완전히 기억한 마법사였습니다"

리포트는 "잘했어요" 같은 단정 문구를 쓰지 않는다.

## 17. 마일스톤 (이 문서 기준)

원칙: **15분짜리 완결 vertical slice를 먼저 만들고, 그게 돌아가는지 확인한 뒤에 나머지 층을 확장한다.** 1층 + 5층 축약판이 사운드와 엔딩 리포트까지 통과해 한 편의 짧은 경험이 되는지가 모든 후속 작업의 전제다.

| M | 목표 | 핵심 산출물 |
| --- | --- | --- |
| M0 | 기준 문서 정리 | 이 문서, `PROJECT_ROADMAP.md` 갱신 |
| **M1** | **15분 완결 vertical slice** | 1층 축약 + 5층 축약 (슬롯 3개) + 핵심 SFX + 엔딩 리포트. 외부 1인이 끊김 없이 15분에 완주 가능 |
| M2 | vertical slice 사용자 테스트 | 5명 / 1·5층 축약 완주 / 인식·NPC 빈도·엔딩 만족도 수집 |
| M3 | 인식 개선 패스 | M2 로그 기반 인식기·힌트 조정, user profile Unity 이식 |
| M4 | 2·3·4층 확장 | §9 각 층의 퍼즐 밀도와 해결 루트를 vertical slice 위에 얹음 |
| M5 | NPC 대사 풀 작성 | §13 6 트리거 × 3~5 변주, ScriptableObject로 분리 |
| M6 | 층별 결정적 모먼트 | §14 9개 + 5층 진엔딩 모먼트 8b 모두 구현 |
| M7 | 5층 클라이맥스 보강 | §9 5층 5/6 슬롯 엔딩 분기와 진엔딩 추가 연출 |
| M8 | 접근성 옵션 | §15 항목 |
| M9 | 엔딩 리포트 폴리시 | §16 헤더 분기, codex 발췌 알고리즘 |
| M10 | 외부 빌드 + 첫 외부 시연 | Windows build, 외부 1인 5층 완주 |

각 M은 1~2주를 기준으로 잡는다. **M1이 가장 큰 단일 마일스톤**으로, 여기서 막히면 M2 이후는 시작하지 않는다. M2는 외부 협조가 필요한 구간이므로 일정에 여유를 둔다.

### M1 vertical slice 범위 정의

- **1층 축약** — 인덱스 룬 3개로 축소 (fire, water, earth 권장), 5 base 중 3개만 의미 있게 작동. 승강 룬 활성화 조건은 1개 작동.
- **5층 축약** — 슬롯 3개로 축소 (정화, 안정, 연결 권장). 통과 조건 2개 만족, 진엔딩 3개 만족.
- **사운드** — 12 SFX 중 핵심 7종 (`cast_base_success` family 변주, `cast_invalid`, `cast_incomplete`, `goal_satisfied`, `floor_complete`, `note_unlock`, `npc_appear`) + `ambient_tower` BGM.
- **엔딩 리포트** — 헤더 분기 동작, 자기 평가 4문항.
- 2~4층은 잠긴 문으로 표시하고 "다음 패스에서 열림" 안내.

## 19. 아직 열어둔 질문

- 0.8초 입력 버퍼가 실제 조작감에 맞는가?
- overlay seal 유지 시간은 몇 초가 가장 자연스러운가? (현재 잠정 5초)
- 한 번의 seal에 overlay를 몇 개까지 붙일 수 있어야 하는가? (현재 잠정 3개)
- 최종 마법진의 슬롯은 6개가 맞는가? 8개로 늘리면 클라이맥스가 길어지지만 피로감도 커진다.
- NPC 컨텍스트 소환 빈도가 너무 잦지 않은가? 5층에서 슬롯마다 등장이 적절한지 vs 5번째 + 마지막만 등장이 더 신비로운지.
- 같은 트리거의 30초 쿨다운이 짧지 않은가? 60초로 늘리면 재촉 느낌은 줄지만 학습 지원이 느려진다.
- 노트의 문장은 얼마나 시적으로, 얼마나 명확하게 써야 하는가? 5층용 NPC 대사와 1층용 NPC 대사의 톤 차이를 둘지.
- NPC 대사를 노트에 항상 자동 기록할지, 플레이어가 따로 책갈피로 골라 저장할지.
- "관찰 모드" (assist 자동 1단계 강화)를 옵션으로 둘지, 항상 켤지.

이 질문들은 구현 전에 프로토타입 조작감과 플레이 테스트로 결정한다.
