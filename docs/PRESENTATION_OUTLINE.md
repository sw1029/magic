# 발표 자료 뼈대 (5~8분)

P8-3의 발표 자료 초안. 슬라이드 단위로 구성하며, `(데이터)` 표시는 플레이테스트 1·2차 결과로 채운다. 시연 영상 2분을 백업으로 준비한다.

> **슬라이드 덱**: 이 아웃라인 기반 7장 뼈대가 [presentation/MagicExamHall_Presentation_Skeleton.pptx](presentation/MagicExamHall_Presentation_Skeleton.pptx)에 있다 (2026-06-12). `(데이터)` 칸은 점선 박스로 표시돼 있어 플레이테스트 결과로 채우면 된다. 스크린샷·QR 자리도 점선 placeholder. 검증 수치(웹 테스트 181, EditMode 105, PlayMode 47)는 2026-06-12 로컬 실행 기준.

## 슬라이드 구성

### 1. 제목 (30초)
- Magic Exam Hall — 맵 바닥에 직접 문양을 그려 시전하는 마법 드로잉 퍼즐
- 한 줄: "정답 레시피가 아니라 관찰과 조합으로 통과하는 입학 시험"
- 스크린샷 1장 (5층 성좌심 or 1층 첫 시전)

### 2. 문제 — 비어 있던 자리 (1분)
- 기존 마법 게임의 두 축: 정답 룬 암기(Arx Fatalis) vs 키 콤보(Magicka)
- 빈 교차점: **손으로 그리는 입력** × **레시피 없는 발견형 퍼즐** × **실패가 단서가 되는 학습 톤**
- 연구 질문: 기호 기반 입력이 재미와 몰입을 만들면서도 실패 이유를 납득 가능하게 설명할 수 있는가 (GAME_DESIGN §1)

### 3. 설계 — 마법 문법 (1.5분)
- base 5종(세계를 바꾸는 동사) + overlay 6종(동사를 바꾸는 장식), `void_cut` 이후에만 서는 `martial_axis` 의존성
- family와 quality의 분리: 형태가 종류를, 품질이 세기·지속을 결정
- 실패 처리: 단계적 힌트 escalator (환경 → 체크리스트 → ghost trace)
- 다이어그램: 관찰 → 드로잉 → 인식/품질 → 세계 반응 → 조합 실험

### 4. 구현 — 웹 검증, Unity 이식 (1.5분)
- 2트랙 구조: Web recognizer lab(빠른 실험·dashboard·survey) → Unity playable(5층 시험장)
- 인식 파이프라인: stroke session → 특징 추출 → family 판정 + quality vector → 세계 효과
- 폴리시: URP 2D 라이트, 절차 생성 SFX/BGM + 파일 우선 로더, 멘토 NPC·codex·엔딩 분기(5/6 통과·6/6 진엔딩)
- 검증 자동화: EditMode/PlayMode 테스트, Windows 빌드 + smoke, CI

### 5. 검증 — 사용자 테스트 (1.5분)
- 프로토콜: 무설명 60분 완주, 입력 버퍼 0.6/0.8/1.0초 A/B (RESEARCH_PROTOCOL)
- (데이터) 1차 N=5: 첫 시전까지 시간, family별 첫 시도 성공률, assist 도달률
- (데이터) 2차 N=3~5: 1차 대비 개선 폭 (인식 튜닝·체감 개선 반영 후)
- (데이터) 설문: 공정성·몰입감 5점 척도 평균

### 6. 결과와 한계 (1분)
- 엔딩 리포트("당신은 이런 마법사였습니다") — 플레이 스타일의 데이터화
- (데이터) 완주율, 통과/진엔딩 비율, 발견 수 분포
- 한계: 인식 휴리스틱의 개인차, 표본 크기, 단일 세션 측정
- 다음: user profile 보정 이식, 외부 배포

### 7. 마무리 (30초)
- "자기 손으로 그은 마법진이 작동하는 첫 순간"이라는 한 가지 경험
- 빌드 다운로드 QR / 저장소 링크

## 시연 영상 (백업 2분)
1. 타이틀 → 새 게임 (10초)
2. 1층: 첫 문양 시전, ghost gesture (30초)
3. 2층: overlay 부착 라벨 변화 (20초)
4. 3층: 같은 다리를 두 방법으로 건너기 (30초)
5. 5층: 5번째 슬롯 → 통과 엔딩 → 리포트 (30초)
